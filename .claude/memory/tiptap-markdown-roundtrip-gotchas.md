`app/components/MarkdownEditor.vue`（textarea→Tiptap 改造，v-model 仍是 markdown 字符串）的两个非显然往返坑：

1. **`@tiptap/extension-image` 在 v3 默认是 block 级**（`inline:false` → group:'block'）。独立 `![img](url)` 解析后成为 doc 的直接 block 子节点，而 tiptap-markdown 序列化器对顶级 block 图片**不加空行分隔**→ 和相邻段落挤到同一行（`![img](url)首页`）。修：`Image.configure({ inline: true })`，让图片行内落进段落（与服务端 markdown-it 把独立图片渲染成 `<p><img></p>` 一致）。代码里已有注释。

2. **测往返保真必须走组件真实的 `loadMarkdown` 路径，别用 `editor.commands.setContent(fullMd)`**。tiptap-markdown 的 Markdown 扩展**覆盖了 setContent**：对字符串 content 先 `parser.parse(content)`（整串当 markdown 解析），会绕过本编辑器的两段式 `splitMarkdown`（`:::` 容器本应作原子 CustomContainer 存 raw、永不进解析器）→ 容器被 markdown-it 的 linkify/autolink 损坏（`https://x` → `<https://x>`、`imqi1.com`→`[imqi1.com](http://imqi1.com)`、每行尾加 `\`）。读编辑器输出要用真实加载后 `editor.storage.markdown.getMarkdown()`，或浏览器里 walk `el.__vueParentComponent`（`.ProseMirror` 是 PM 建的、无该字段，要往上找祖先）拿 `editor`。

3. **StarterKit 自带 CodeBlock 能保留 language 但无修改入口**：v3 的 `@tiptap/extension-code-block` parseHTML 从 `<code class="language-js">` 提取语言（`languageClassPrefix:'language-'`），renderMarkdown 输出 ` ```js `，往返**不丢**语言（实测 cid 1008 的 `py+study.py` 都在）；但 `addCommands` 只有 setCodeBlock/toggleCodeBlock，**没有任何设置语言的命令**。textarea 时代作者可直接改 ``` 后的语言标记，迁 Tiptap 后代码块整体化、语言看不见也改不了。修：扩展用 `app/components/markdown-editor/extensions/CodeBlockLowlightWithLang.ts`（见点 6）——`CodeBlockLowlight.extend({ addNodeView(){ return VueNodeViewRenderer(CodeBlockNodeView) } }).configure({ lowlight: createLowlight(common) })`，只覆盖 addNodeView，parseHTML/renderHTML/parseMarkdown/renderMarkdown/input rule（```js<Enter> 自动识别）/快捷键全保留，tiptap-markdown 往返不受 NodeView 影响（序列化走 schema 不走 DOM，lowlight 走 DOM decoration）。StarterKit 用 `configure({codeBlock:false})` 关内置。NodeView（`CodeBlockNodeView.vue`）用 `NodeViewWrapper as="pre"`（仍是 pre，匹配 `.ProseMirror pre` 全局样式）+ 右上角 absolute 一个**普通文本 `<input>`**（`@mousedown.stop` 防 ProseMirror 抢焦点），`NodeViewContent as="code"` 作 contentDOM；input 双向绑 `node.attrs.language`，空串↔null（**null 才序列化成无语言 ` ``` `**，空串不行）。早先 `<input :list>`+`<datalist>`+`useId()` 的写法已改回纯文本框。

可接受的往返差异（plan 容差内、渲染等价）：表格列对齐空格被压成 compact、表格分隔符 `|-------|`→`| --- |`、裸域名被 linkify（服务端也 linkify:true，渲染同）、代码块尾空行被 trim、`-`单元格→`\-`。容器部分必须 0 差异（字节级）。相关：[[cn-is-pure-clsx-no-tailwind-merge]] 的 scoped CSS 兜底在 NodeView 用了 `not-prose`。

4. **`editorProps.handlePaste` 必须是同步函数（返回 `boolean|void`），绝不能 `async`**。Tiptap 把 editorProps 原样 `...editorProps` 展开进 `new EditorView()`（不做 async 包装）；ProseMirror 粘贴路径 `doPaste` 用 `if (view.someProp("handlePaste", f => f(view, event, slice))) return true` 判断——`someProp` 同步取返回值，async 函数同步返回的是 **Promise**（恒 truthy）→ `doPaste` 立即 return、**跳过默认粘贴事务**。后果：普通文本/非图片粘贴**全失效**（只有图片路径因同步调了 `event.preventDefault()`+手动 insert 而能用，掩盖了 bug）。修：签名改 `function handlePaste(view, event): boolean`，非图片同步 `return false` 放行默认，图片同步 `preventDefault()`+`return true`，再 `void uploadPastedImages(...)` fire-and-forget 跑异步上传。同区域两个配套修：① 粘贴先插 `src:"uploading"` 占位时加 `suppressEmit` 闸门挂起防抖 `emitMarkdown`，`finally` 里立即 `writeMarkdownOut()` flush 最终态，否则占位 URL 会被中间态写回 model（父组件窗口内保存就落库）；② `item.getAsFile()` 返回 null 要调 `removePlaceholder(ed, uploadId)` 清占位，否则孤儿坏图残留。

5. **图片段落底部异常大间隙（渲染坑，非往返）**：`Image.configure({inline:true})` 的图片段落 DOM 是 `<p><img><img.ProseMirror-separator><br.ProseMirror-trailingBreak></p>`。Tailwind preflight 给 img 设 `display:block` → 图片独占行；同段的 `.ProseMirror-separator`（0宽 inline 占位 img，光标桥）和 `.ProseMirror-trailingBreak` 被挤到图片下方**独占一整行行高（line-height 28.8px）**，造成图片与下方元素 ~45px 异常大间隙（正常 p+p 仅 16px margin）。排查时 `<br>` 行框高度由父 line-height 决定、设 BR 自身 `line-height:0` 无效（实测仍 22px），只能 `display:none`。难点：prosemirror-view 注入了 `img.ProseMirror-separator{display:inline!important}`，普通 scoped CSS 被压制；必须 `.markdown-editor :deep(.ProseMirror p:has(> img) .ProseMirror-separator, ...trailingBreak){display:none!important}`——scoped 特异性 0,5,1 > 其 `img.ProseMirror-separator` 0,1,1，!important 平局后比特异性胜。`:has(> img)` 限定只动图片段落，纯文字/空段落的占位保留（空段落需 trailingBreak 维持最小高度，否则光标看不见）。相关 [[cn-is-pure-clsx-no-tailwind-merge]] 进阶：不只源序，attr/类型选择器组合会抬升特异性。

6. **编辑态代码块语法高亮（lowlight，2026-08-08 加）**：后台编辑器代码块原本单色无高亮（旧 `MarkdownEditor.vue` 注释「无 Shiki 高亮」）。接 `@tiptap/extension-code-block-lowlight`（peer 与 v3.29.2 全匹配，配 `lowlight@3`）。要点：① `CodeBlockLowlight` 只覆写 `addOptions/addProseMirrorPlugins`（注入一个用 `Decoration.inline` 给每个 token 画 `<span class="hljs-xxx">` 的插件），**没有 addNodeView**——所以在它上面 `.extend({ addNodeView(){ return VueNodeViewRenderer(CodeBlockNodeView) } })` 叠加语言输入框，二者**共存无冲突**：装饰由 PM 写进 NodeViewContent 的 contentDOM，与 NodeView 无关。② 高亮走 decoration **不碰文档模型**，节点名仍是 codeBlock、language 属性照旧，`tiptap-markdown` 往返零差异（容器须 0 差异那条不受影响）。③ lowlight 实例用 `createLowlight(common)` 一行注册 37 种常见语言（js/ts/py/go/rust/java/c/cpp/json/yaml/sql/bash/html(xml)/css/md…），覆盖前台 Shiki 大头；其余语言编辑器纯文本、前台仍 Shiki 高亮。语言留空/未注册时插件 `highlightAuto` 尽力推断（默认行为，每按键重算，可接受）。④ token 类名：highlight.js v11 经 lowlight 产出函数/类名 span 同时带 `hljs-title` + 裸 `function_`/`class_`（**第二段无 hljs- 前缀**），但简单 `.hljs-title` 选择器即命中，无需写转义的复合选择器。配色复用 `app/shiki/island_{light,dark}.ts`（comment/string/number/keyword/function/type/tag…）保持编辑态与前台一致。扩展文件 `markdown-editor/extensions/CodeBlockLowlightWithLang.ts`（旧的纯 NodeView 版 `CodeBlockWithLang.ts` 已删）。
