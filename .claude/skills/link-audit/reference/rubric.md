# 机审判定口径与报告读法

> 本 skill **不再做模型复核**：判定直接采用百度内容审核的原始结论。
> 本文件说明「审查范围」「机审结论怎么映射成置信度」「报告里的位置怎么读」「误报怎么识别」。

## 〇、审查范围（重要）

**只判各友链/订阅源「自己的内容」。** 对方站点页面里属于第三方/其他站点的部分，在抓取阶段就屏蔽掉，不送审：

| 屏蔽对象 | 说明 |
| --- | --- |
| 站外链接条目 | 他们的友链列表、外链聚合、导航条目（含锚文本与紧跟的「｜描述」文案） |
| 友链/导航类板块 | 标题含 友链 / 推友 / 朋友圈 / 博客圈 / 链接墙 / 导航站 等的整段内容 |
| 评论区 / 留言板 | 访客写的内容，不是站主的 |

理由：那些内容由对方站点自己负责，不该记到本站头上。manifest 的 `notes` 会记录每个目标屏蔽了多少（站外链接条目 / 板块 / 留言区），便于核对范围是否真的收窄了。

仍会审的：
- **我们自己站上呈现的内容**：友链名称与描述、订阅源名称（`00-info.txt`）
- **对方自己的原创内容**：首页/文章正文、订阅文章的标题/摘要/正文

## 一、结论映射

百度自定义文本审核 v2 的 `conclusionType`：

| conclusionType | 含义 | 本 skill 的判定 | 置信度 | 是否进处置清单 |
| --- | --- | --- | --- | --- |
| 2 | 不合规 | 违规 | **0.90** | 是 |
| 3 | 疑似 | 疑似 | **0.65** | 是 |
| 1 | 合规 | 合规 | — | 否 |
| 4 | 审核失败（技术性失败） | 未覆盖 | — | 否（进「需重审」清单） |
| 0 / 缺失 | 未知 / 请求异常 | 未覆盖 | — | 否（进「需重审」清单） |

置信度是**由结论类型确定性映射**的，不是模型打分。

**同一目标多块结论的聚合按「严重度序」而非数值大小**：2（不合规）> 3（疑似）> 4（审核失败）> 1（合规）。数值大小会出错 —— 4 的数值最大却只是技术性失败，按 `Math.max` 取最差会让「不合规」被「审核失败」盖掉，导致违规目标漏判。有块未审成时该目标进「需重审」清单，结论只代表已审部分。

## 二、位置语义

机审返回的每一处命中都带：命中词、在正文里的**字符区间**、风险子类、风险描述、命中概率。本 skill 的处理：
- 字符区间优先用**命中词在快照正文里实搜**定位（百度返回的 `positions` 字段语义不稳，实搜更准）；
- 报告里给出「命中词 + 字符区间 + 上下文片段 + 风险子类」，指向具体是快照的哪个文件、哪一段；
- `logId` 一并保留——百度侧的审核凭证，处置留档用。

快照文件构成：
- `00-info.txt` — **本站自己展示**的友链名称/描述、订阅源名称（直接渲染在本站页面上，风险最直接）
- `00-home.txt` / `01-page.txt`… — 对方站点的首页与站内抽样页
- `post-*.txt` / `live-*.txt` — 订阅文章（本站 `/subscribes` 直接渲染其标题与摘要）

## 三、误报要认出来（处置前必看）

**全量实测（2026-10-29，40 个目标 / 392 份快照）：34 个目标被机审标记，逐条看命中上下文后，几乎没有能直接下线的。** 误报集中在下面几类（只说类型，不列词表）：

| 误报形态 | 机审判成 |
| --- | --- |
| 站点名 + 域名的组合 | 网址不合规 |
| 友链板块名、联系方式类板块词 | 兼职代理 / 联系方式-网址 / 关注引流 |
| 纯数字串 | 涉政类（领导人相关） |
| AI 创作、日常动作、床上/室内等普通表述 | 涉黄类 |
| 口语感叹词、脏话转述 | 辱骂类 |
| 拼接词、泛化生活词 | 歧视类 / 封建迷信 |
| 网络流行语 | 网络黑话烂梗 |
| 普通网盘/外链、字体/字体包站点 | 禁止投放广告 / 虚假权威营销 |

**结论：机审标记 ≠ 违规成立。** 判断标准是「上下文里是不是违规内容**本体**（售卖/导流/传播）」，而不是「有没有出现被命中的表达」。处置前按「命中词 + 风险子类 + 上下文片段」逐条过目：
- 上下文确为违规内容本体 → 下线；
- 上下文是正常表达 → 记为误报，可在 `verdicts.json` 里人工标注覆盖（见下）。

报告的「建议」列已按命中子类分级：命中高危子类（涉黄/赌博/毒品/涉恐/涉政/诈骗等）标 **优先**人工复核，其余标「人工复核」——**机审结论本身不构成下线建议**。

## 四、可选的人工标注

`$WORK/verdicts.json`（非必需，存在即生效）可覆盖某目标的判定与建议：

```json
{
  "findings": [
    {
      "targetKind": "link",
      "targetId": 25,
      "verdict": "误报",
      "recommendation": "保留观察",
      "basis": "命中词为板块名「友情链接」，上下文正常"
    }
  ]
}
```

`report.ts` 会用这里的 `verdict`/`recommendation`/`basis` 覆盖机审结论，并在详述里显示「人工标注」。
